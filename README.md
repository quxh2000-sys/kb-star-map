# 知识库星图工作台 · 使用说明


> **本仓库是「知识库星图工作台」的源码与发行版。**
> 安装只需一条命令（见下方「三步走」），**不提供压缩包**——安装器按 `dist/files.json`
> 清单逐文件从 Gitee 取回并校验。已安装的同事用 `kbs update` 或界面里的「检查更新」升级。
> 请勿把生成出来的星图 HTML 提交进仓库——它内嵌了整库笔记摘要。

> 把你的 Markdown 笔记目录变成一张可以缩放、筛选、回放的星图。
> Obsidian、Logseq、Typora 写的库，或者你自己攒的一个装满 `.md` 的文件夹，都可以。
> 笔记内容全程在本机处理，不上传。只有你主动点「检查更新」/ 执行 `kbs update` 时才联网，
> 而且只下载工具文件本身，请求里不含任何笔记内容。

## 一、它能帮你看到什么

- **全库结构**：每篇笔记是一个光点，笔记之间的链接是连线，按资产类型聚成星系
- **结构健康**：底部状态带显示当前节点数、待补来源、低证据、待治理节点
- **变化轨迹**：拖动「时间回放」可以看到知识库是怎么一天天长起来的
- **按需分组**：自己定义分组着色（例如把所有跟某个产品相关的笔记染成一个颜色）
- **查得到**：搜索标题、路径、摘要、标签；点节点看详情，可复制笔记路径

## 二、你需要准备什么

| | 要求 | 说明 |
|---|---|---|
| 笔记目录 | 一个本机文件夹 | 里面装着 `.md` 笔记。**不需要装 Obsidian** |
| 笔记之间的链接 | `[[双链]]` 或 `[文字](相对路径.md)` | 两种写法都认；没有链接的笔记会显示为孤点 |
| Python | **3.9 或更高** | macOS 若装过 Xcode 命令行工具，通常已自带；Windows 需自行安装 |
| 网络 | 可选 | 只在安装与「检查更新」时用到（都走 Gitee，国内可达） |
| PyYAML | 安装器会**自动尝试安装** | 装不上时会给出提示命令 |

> Windows 安装 Python 时，**务必勾选 “Add Python to PATH”**，否则命令找不到它。

## 三、三步走

### 第 1 步：安装（一行命令）

**Windows**：打开 PowerShell，粘贴这一行回车：

```powershell
$u='https://gitee.com/quxh20000/kb-star-map/raw/master/install.ps1'; $p="$env:TEMP\kbs-setup.ps1"; irm $u -OutFile $p; powershell -NoProfile -ExecutionPolicy Bypass -File $p
```

> 为什么不用更短的 `irm … | iex`：带 BOM 的脚本经 `iex` 传入时，BOM 会被当成首行内容而报错。
> 上面这条是"先存成文件再以文件方式运行"，两个问题都避开。

**macOS / Linux**：打开终端，粘贴这一行回车：

```bash
curl -fsSL https://gitee.com/quxh20000/kb-star-map/raw/master/install.sh | bash
```

装完会得到一个 `kbs` 命令（工具装在用户目录，不往笔记库里塞任何东西）。

### 第 1.5 步：跑起来

```bash
cd "你的笔记库目录"
kbs
```

它会生成星图、启动本地管理模式并打开浏览器。

首次在一个**全新的**笔记库上运行时，会写一份分类规则模板到
`系统/知识库可视化工作台/资产分类规则.yaml`；如果这个库早就在用了，
不会凭空塞规则文件（那样会把原有分类整个改掉）。

其它命令：

| 命令 | 作用 |
|---|---|
| `kbs` | 用当前目录当笔记库，生成并打开 |
| `kbs "D:\我的笔记"` | 指定笔记库 |
| `kbs build` | 只生成 HTML，不启动服务 |
| `kbs update` | 更新工具（也可在界面右上角点「检查更新」） |
| `kbs check` | 查看是否有新版本 |
| `kbs stop` | 停止本地服务 |
| `kbs version` | 查看版本与安装位置 |

### 第 2 步：改分类规则（**别跳过这步**）

打开 `<你的目录>/系统/知识库可视化工作台/资产分类规则.yaml`，把你自己的目录填进去。

**为什么必须改**：星图靠目录或 frontmatter 判定「资产类型」。规则里默认的目录名是给示例用的，
你的目录结构若不匹配，笔记会**全部落进「未分类」**——能看见，但都挤在一个星系里，看不出结构。

如果你的笔记 frontmatter 里已经写了 `knowledge_type` 或 `dimension`，这一步可以放宽；
两者都没有时，目录规则就是唯一依据。

改完重新运行一次安装器即可刷新。

### 第 3 步：打开

- **只读浏览**：直接双击 `<你的目录>/系统/知识库可视化工作台/知识库可视化工作台.html`
  （用 Chrome 或 Edge 效果最好）。这样打开是「分享快照」模式，不需要服务。
- **要能点节点打开笔记 / 用维护面板**：在笔记库目录执行 `kbs`
  → 启动本地管理模式并自动打开浏览器。

### 以后怎么升级

两种方式，随便哪种：

- **点一下**：进本地管理模式 → 右上角「⚙ 设置」→「检查更新」，确认后自动完成。
- **敲一行**：在终端执行 `kbs update`。

升级只替换 `~/.kb-star-map` 下的工具文件，并按清单清理上一版删掉的文件；
`设置.yaml`、`更新配置.yaml`、`升级备份/` 会保留。
笔记库里的 `资产分类规则.yaml`、`运营任务草稿/` 以及你自己的文件都不会被动。

> 工具装在用户目录，**不往笔记库里塞任何程序文件**。

## 四、两种模式的区别

| | 分享快照（直接双击 HTML） | 本地管理模式（`kbs`） |
|---|---|---|
| 看星图、筛选、回放、分组 | ✅ | ✅ |
| 看节点详情、复制笔记路径 | ✅ | ✅ |
| 点按钮打开笔记 | 改为**复制路径**并提示 | ✅ 直接打开 |
| 维护知识（改/新增笔记） | 不可用 | ✅ |
| 需要启动服务 | 不需要 | 需要（关掉窗口即停） |

分享快照适合**把 HTML 直接发给别人**——对方不需要装任何东西。

### 打开笔记用的是哪个程序

本地管理模式点节点时：

- 装了 **Obsidian** → 用 Obsidian 打开对应笔记
- 没装 Obsidian → 用**系统默认程序**打开这个 `.md` 文件（你平时双击 `.md` 用哪个就用哪个）
- 想强制指定：进「⚙ 设置」→「笔记」→「打开笔记的方式」，可选**自动 / 总是用 Obsidian / 总是用系统默认程序**

## 五、分类规则怎么写

判定顺序（前面的优先）：

```
① frontmatter 的 knowledge_type
② frontmatter 的 dimension（九维分类）
③ frontmatter 的 type / category
④ 规则文件里的 path_rules（按目录前缀，自上而下第一个匹配生效）
⑤ fallback（都没匹配上时归入）
```

可用的资产类型：

`来源资料` `拆解记录` `知识原子` `专题知识` `需求记录` `方案成果` `验证反馈` `治理规则` `运行记录`

例子：

```yaml
fallback: 未分类

path_rules:
  - ["01-原始资料/", "来源资料"]
  - ["02-知识原子/", "知识原子"]
  - ["03-方案/", "方案成果"]
```

> `运行记录` 是一个**默认隐藏**的类型，适合放日记、模板、更新日志这类不该出现在主图里的内容。
> `fallback` 请不要设成 `运行记录`——那样未匹配的笔记会全部消失。

## 六、常见问题

**命令跑不动 / 提示没有 Python**
确认已装 Python 3.9+。Windows 安装时务必勾选 **Add Python to PATH**；
macOS 可执行 `xcode-select --install`，或到 python.org 下载安装。

**公司网络拦住了 PowerShell**
脚本本身走 Gitee（国内可达）。若公司策略禁止下载并执行脚本，
用系统自带终端按上面的 `curl` 那条试；仍然不行就需要走离线方式（见仓库 Issue）。

**提示找不到 Python 3.9+**
macOS 在「终端」执行 `xcode-select --install`；Windows 到 python.org 下载安装。

**必须用 Obsidian 吗**
不用。星图只读你的 `.md` 文件，不依赖 Obsidian 程序、配置或插件。
装了 Obsidian 的额外好处只有一条：本地管理模式点节点时用 Obsidian 打开笔记。
不装则用系统默认程序打开，效果一样。

**星图打开是空白的 / 只有几个点**
多半是分类规则没配。检查 `资产分类规则.yaml` 里的 `path_rules` 是否命中你的目录。
另外「显示后台记录」默认关闭，已归入“运行记录”的笔记不会出现在主图上。

**连线上没有几条 / 关系很少**
星图的关系来自笔记里写的链接。支持两种写法：

```markdown
[[另一篇笔记]]                      双链，按笔记名找
[另一篇](子目录/另一篇笔记.md)        标准 Markdown 链接，按相对路径找
```

标准链接的路径**相对于当前笔记所在目录**（Markdown 通用规则）。
链接指向不存在的笔记时不会画线，并在「待补来源」里给出提示。

**页面显示「当前查看环境未启用交互功能」**
说明用的浏览器不支持或禁用了 JavaScript，换个浏览器（Chrome / Edge）。

**能不能发给我同事看**
可以。只要把 `知识库可视化工作台.html` 这一个文件发过去，对方双击就能看，不需要装任何东西。
（但请留意：这个文件内嵌了你库里所有笔记的摘要。）

## 七、边界

- 星图是**生成时的快照**：知识库变了要重新生成（本地管理模式下重建后，页面会**自动刷新**）
- 网页端不改你的笔记；撰写与维护仍在你自己常用的编辑器里进行
- 只有主动点「检查更新」/ 执行 `kbs update` 时才联网，而且只下载工具文件本身
  （按 `dist/files.json` 清单逐文件取回并校验 sha256），**请求里不含任何笔记内容**
- 把 `~/.kb-star-map/更新配置.yaml` 的 `manifest_url` 留空，就完全不联网
- 其余功能全部在本机完成，不上传任何数据
